AI Search Observability

Ask an AI the same shopping question ten times and it names a different set of shops. We measure how often each Thai retailer is named, recommended and cited by Gemini, ChatGPT, Perplexity and Google AI Mode, and we put a confidence interval on every number.

Case study: game consoles (PS5, Switch 2) sold online in Thailand. Target shop: Tinzshop, tracked against about 10 competitors.

Objective 3 · adaptive sampling

Stop asking once the answer is clear

Each dot is one repeat of the same query; a filled dot means the shop was named. After every repeat the 95% Wilson interval is recomputed. Once the whole interval sits above or below 50%, more repeats cannot change the decision, so the collector stops. Same rule as collect.py: at least 3, at most 10 repeats. Draws here are simulated.

– fewer queries than always asking 10 times, in this run. The proposal target is at least 25%, measured on real collection.
Tools

What runs in the pipeline, and what we build it with

runs in the pipeline
  • Python 3 standard libraryCollector, extractor, statistics and reports, with no other dependencies.
  • PlaywrightDrives a real Chromium browser to ask the free web engines the way a person types. Stops at any login wall or CAPTCHA and never bypasses it.
  • Gemini API, free tierBaseline with web search off: what the model knows without searching.
  • Manual paste toolFor engines we cannot automate, a person asks in the app and pastes the answer, so the data has the same shape.
  • JSONL + HTML dashboardAppend-only raw answers, so the analysis can be re-run without asking again.
used to build it
  • Claude Code, an AI coding agentPair-programs the adapters, statistics and dashboard; runs the code and fixes what fails.
  • Playwright MCPLets the agent open and inspect an engine's live page, so it can write the adapter and repair it when the layout changes.
  • Cloud sessionsIndependent tasks such as the dashboard, the tests and this page run as parallel cloud agents against the GitHub repo.
  • GitHubHolds code, tests and the query set. Raw data and API keys stay out of the repo.

The AI tools help write the software. They do not produce the measurements: every number in the report comes from saved raw answers and fixed rules we can test.
